wip-healthcheck now binds gateway liveness to the configured launchd service PID, the listener that PID owns, and bounded health and readiness probes. Process-name matching remains available as diagnostic context but can no longer restart a healthy renamed process. Endpoint failures require the configured consecutive-failure threshold, while missing services and mismatched listeners still fail immediately under the existing restart rate limit. A non-remediating re-enablement preflight verifies the current gateway token against an authenticated endpoint before the watchdog is loaded.
